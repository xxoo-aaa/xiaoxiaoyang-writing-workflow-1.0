# 全局规则

> 所有次级技能和整个写作工作流必须遵守的统一规范。这是整个系统的"宪法"。

## 一、文件命名规范

### 1.1 项目文件命名
- 格式：`类型_名称_版本.扩展名`
- 示例：`长篇_潮汐之城_v0.3.md`、`短篇_最后一班地铁_终稿.md`、`剧本_暗夜行者_v1.2.fountain`
- 版本号：v0.1（大纲）→ v0.5（初稿）→ v1.0（定稿）→ v1.1（修订）
- 日期可选：`长篇_潮汐之城_20260903_v0.3.md`

### 1.2 模块内文件命名
- 技能定义文件统一命名为 `skill.md`
- 模板文件统一放在 `templates/` 目录，命名为 `模板名称.md`
- 方法论文件命名为 `方法名称.md`

## 二、写作质量标准

### 2.1 各阶段完成度定义

| 阶段 | 完成标准 |
|---|---|
| 创意阶段 | 能用一句话说清核心概念，有明确的冲突和钩子 |
| 大纲阶段 | 有完整的三幕结构，每幕有明确的转折点和高潮 |
| 人物阶段 | 主角有清晰的动机、创伤、弧光；主要配角有独立目标 |
| 初稿阶段 | 故事完整讲完，所有主要场景都有内容，允许粗糙 |
| 修订阶段 | 逻辑通顺，节奏合理，人物一致，文字流畅 |
| 定稿阶段 | 通过质量保障检查，无明显硬伤，达到可投稿/发布水平 |

### 2.2 场景质量检查清单
- [ ] 场景有明确的目标（角色想要什么）
- [ ] 场景有冲突（什么阻止了他）
- [ ] 场景有转折（结束时和开始时状态不同）
- [ ] 场景有感官细节（不是只有对话和动作）
- [ ] 场景推进了情节或人物（不是可有可无的过渡）
- [ ] 场景开头不是无效铺垫（3行内进入冲突）
- [ ] 场景结尾有钩子或余韵（不是平淡结束）

### 2.3 人物一致性检查
- [ ] 人物的行为符合其性格和动机
- [ ] 人物的语言风格前后一致
- [ ] 人物的外貌/身份/背景设定前后一致
- [ ] 人物的变化有铺垫和过程（不是突然转变）

## 三、版本管理约定

### 3.1 草稿版本标记
- 在文档顶部标注版本号和日期
- 示例：
  ```
  版本：v0.3（初稿第3次修改）
  日期：2026-09-03
  状态：修订中
  待办：第3章冲突不够，结尾钩子需要加强
  ```

### 3.2 重大变更记录
- 大纲级别的变更（增减人物、修改主线、调整结局）必须记录
- 记录格式：`[日期] 变更内容 → 变更原因 → 影响范围`

### 3.3 Git 提交建议（如使用 Git 管理稿件）
- 每次完成一个场景或一次修订后提交
- 提交信息格式：`[模块] 动作描述`
- 示例：`[第3章] 完成初稿`、`[人物] 深化反派动机`

## 四、模板使用规范

1. **复制使用**：从 `templates/` 复制模板到你的项目目录中使用，不要直接修改原模板
2. **自定义**：可以根据项目需要增删模板字段，但核心结构建议保留
3. **反馈**：如果模板有改进建议，记录下来，定期更新模板库
4. **版本**：模板有版本号，使用时注意是否为最新版本

## 五、技能调用规范

### 5.1 输入要求
- 调用任何技能前，先提供项目背景（项目名称、类型、当前阶段）
- 提供具体的需求描述（不是"帮我写个人物"，而是"帮我设计一个30岁的女侦探，有创伤后应激障碍，正在调查一起连环杀人案"）
- 有参考材料时一并提供

### 5.2 输出要求
- 技能输出必须结构化（标题、列表、表格）
- 给出的建议必须具体可执行
- 标注哪些是"必须做"，哪些是"可选建议"
- 输出末尾给出下一步建议

### 5.3 多技能协作
- 上一个技能的输出作为下一个技能的输入
- 中心技能负责整合，避免信息丢失或矛盾
- 发现前后矛盾时，以最新版本为准，并记录变更

## 六、内容安全规范

1. 所有创作内容必须遵守法律法规和平台规则
2. 涉及敏感题材时，先调用 `24-内容审核` 技能进行风险评估
3. 不创作危害国家安全、破坏社会稳定、侵犯他人权益的内容
4. 引用他人作品时注明来源，避免抄袭
5. 涉及真实人物时注意名誉权和隐私权

## 七、持续改进

- 每次完成一个项目后，调用 `26-复盘与成长` 技能进行复盘
- 把复盘发现的方法论和模板改进更新到对应模块
- 定期整理 `20-素材与知识库`，沉淀金句、场景、人物原型
- 工作流本身也在持续迭代，欢迎提出改进建议

## 八、仓库操作与治理规范（v1.0.1 新增）

### 8.1 操作权限规则

**默认状态：只读 + 建议**
- AI只能读取仓库内容、回答问题、提供方案建议、设计模块架构
- 即使用户提出"加一个XX模块"，也只给出方案设计和归类判断，不直接写文件
- 任何对仓库的修改，先说明"将要改什么、为什么改、影响哪些文件"，等用户确认

**触发写入的明确指令：**
- 用户说出"更新""写入""上传""提交""改仓库""执行""就这么办"等明确执行指令时，才开始编写文件并上传
- "先看看方案"→ 只给方案，不动手
- "可以，更新吧"→ 开始执行

### 8.2 新需求自主归类判断规则

遇到新需求时，AI**自主判断**归类，不给用户选择题，直接给结论。

**判断优先级：**
1. 现有模块已覆盖该功能70%以上 → 归入现有模块，作为补充章节，不新建
2. 现有模块只覆盖30%以下，且新需求有独立方法论体系 → 新建模块
3. 跨模块的通用规则/约束 → 归入本全局规则
4. 空白可复用的表单 → 归入templates/
5. 调度逻辑/意图识别/工作流串联 → 更新中心技能SKILL.md

**判断依据是功能本质，不是名称。**

**输出格式（只有结论，没有选择题）：**
```
【判断结论】
- 归类：新建模块 / 补充XX模块 / 归入全局规则 / 归入templates / 更新中心技能
- 理由：一句话说明（与现有模块的重叠度/区别点）
- 影响范围：需要同步修改哪些文件
- 行动方案：具体要写什么、改什么
```
用户说"更新"即执行，说"不对"即重新判断。

### 8.3 提交前冲突审核机制

每次执行仓库更新前，必须先做冲突审核：

1. **功能重叠检测**：新模块核心功能是否与现有模块重复？重叠度多少？
2. **编号与命名冲突**：新模块编号是否接续当前最大编号？目录名是否重名？
3. **架构层级冲突**：属于哪个层级？是否破坏"一个中心调度多个次级"的关系？中心技能意图识别表是否需要同步更新？
4. **依赖冲突**：新模块是否依赖其他模块？修改现有模块时是否会影响引用它的其他模块？

**防护措施：**
- 新增模块是纯增量的，不影响现有模块
- 修改现有文件时先读取GitHub最新内容，做增量追加，不用本地旧版本覆盖
- 上传前检查目标目录/文件是否存在，避免覆盖
- 上传后验证：检查现有模块完好无损，抽查2-3个现有模块内容确认未被改动
- 可回滚：新增模块不满意可直接删目录，修改文件有Git提交历史可回退

### 8.4 仓库结构铁律

| 位置 | 放什么 | 不放什么 |
|------|--------|----------|
| 根目录 | SKILL.md（中心技能）、README.md、.gitignore | 模块文件、草稿、临时文件 |
| 编号-模块名/ | 只放skill.md | 模板、图片、其他文件 |
| templates/ | 所有空白模板 | 模块文件 |
| 99-全局规则/ | 全局规则文档 | 模块文件 |

**内容铁律：**
- 每个skill.md必须有统一结构：技能定位→何时调用→输入输出→核心方法论→关键模板/清单→调用示例
- 模块之间功能边界清晰，不重复造轮子；跨模块引用用相对链接，不复制粘贴
- 编号一旦确定不随意更改，新增模块接续最大编号
- 不删除现有模块，只做新增和修改（除非用户明确要求删除）

**版本铁律：**
- 每次更新在README.md版本记录中追加一条（日期、改了什么）
- 大的架构变更必须用户明确确认
- 每次提交的commit message写清楚改了什么

### 8.5 最大化技能调用机制

- **意图识别**：用户说人话，中心技能自动匹配模块，不需要记技能名
- **一键工作流**：常见文体（短篇/长篇/剧本/短剧）自动串联多模块
- **渐进式引导**：中心技能通过项目记忆判断用户当前阶段，推荐下一步；用户有模糊想法时推荐27-写作搭档
- **模块联动**：每个模块定义标准输入输出格式，上一个模块的输出直接作为下一个模块的输入

## 九、六维创作质量标准（v1.1 新增）

> 本标准适用于所有模块、所有阶段、所有产出。每个阶段完成后必须对照自检。这是整个体系的质量基石。

### 9.1 人味标准（反AI味九条）

**写作时必须遵守：**

1. **禁止情绪标签**：不写"他感到愤怒/悲伤/喜悦"，改用生理反应（拳头攥紧/喉咙发紧/嘴角不受控制地上扬）+ 动作 + 他人反应，三选二
2. **禁止逻辑过渡词**：不写"首先/其次/然而/因此/于是/接着"，用动作和场景自然过渡
3. **段落长度必须有变化**：每段不超过5句，必须有至少一段是1-2句的极短段；禁止连续三段长度相近
4. **排比不超过两句**：超过两句就拆成散句
5. **成语/四字词语不扎堆**：连续两个四字词语就必须替换一个为具体描写
6. **细节必须具体**：不写"阳光很好/房间很乱/她很漂亮"，必须具体到"阳光从窗帘缝切进来照在没洗的杯子上/床上堆着三件外套最上面那件是前女友的/她左眼下面有颗痣笑起来会动"
7. **对话必须不完整**：每段对话符合至少两条——说半句被打断/答非所问/有潜台词/结束时不了了之；禁止每个人都说完整的话
8. **开头必须从动作/细节/对话切入**：禁止从环境描写或心理活动切入
9. **结尾禁止总结/点题/升华**：必须停在动作/画面/对话/未完成的念头上

**自检清单（每段写完逐条检查）：**
- [ ] 有没有"感到+情绪词"？有就改
- [ ] 有没有逻辑过渡词？有就删
- [ ] 有没有连续三段长度相近？有就打碎
- [ ] 有没有排比超过两句？有就拆
- [ ] 有没有成语扎堆？有就替换
- [ ] 有没有通用细节（很好/很乱/很漂亮）？有就具体化
- [ ] 对话是不是每个人都说完整的话？是就改得不完整
- [ ] 开头是不是在环境/心理描写？是就换到动作/细节/对话
- [ ] 结尾是不是在总结/点题？是就删掉最后一段

### 9.2 创新标准

**每个作品必须满足：**

1. **至少3个创新点**：核心设定创新1个 + 人物创新1个 + 结构/反转创新1个
2. **每个创新点必须标注**：在大纲和创作边界档案中写明"创新点：XX，不是常见的XX套路"
3. **反对伪创新**：换皮不换骨不算创新（把男主换成女主但故事一样不算），必须是核心设定/视角/结构的创新
4. **独特性检查**：每个创新点必须通过"这个设定在同类作品里常见吗？"的检查，常见就重新生成

**创新生成五法（所有模块生成内容时可用）：**
- **跨界碰撞**：两个不相关的元素结合（外卖员+时间循环）
- **视角反转**：从没人写过的视角写经典故事（从反派视角写英雄）
- **假设颠覆**：把经典设定反过来（如果英雄其实是反派培养的棋子）
- **类型混搭**：两个类型核心元素融合（科幻+乡村）
- **小众挖掘**：少有人写的群体/场景/议题（入殓师/凌晨四点的医院/数字遗产）

### 9.3 逻辑标准

**人物逻辑：**
- 每个人物的行为必须符合其动机、性格、经历
- 人物变化必须有铺垫，不能突然转变
- 人物语言风格必须统一，不能前后像两个人

**情节逻辑：**
- 每个事件必须有因果关系，不能凭空发生
- 巧合只能用来引发麻烦，不能用来解决麻烦
- 主角解决问题必须靠自己的能力/选择，不能靠外部救援

**世界观逻辑：**
- 世界观规则必须自洽，规则之间不能矛盾
- 超自然/科幻设定必须有内部逻辑，不能想怎样就怎样
- 社会规则必须符合世界观设定

**时间线逻辑：**
- 事件发生顺序必须一致，不能前后矛盾
- 人物年龄、季节、时间流逝必须准确
- 伏笔必须有回收，回收时必须和前面的伏笔对得上

**检查方法：**
- 人物逻辑链：列出主角每个关键行为→动机→是否成立
- 情节因果链：列出每个关键事件→原因→结果→是否合理
- 世界观自洽：列出所有规则→检查是否有矛盾
- 时间线核对：列出所有事件的时间→检查顺序和间隔

---

### 9.4 准确标准

**细节准确：**
- 职业细节准确（医生做手术的流程、律师出庭的程序、程序员写代码的场景）
- 历史细节准确（时代背景、服饰、用语、社会规则）
- 科技细节准确（现有科技不能写错，未来科技要有逻辑）
- 法律/医疗/金融等专业领域细节必须准确，不能想当然

**情感准确：**
- 人物面对事件的反应必须符合心理规律
- 情绪递进必须有层次，不能突然爆发
- 不同人物对同一事件的反应必须符合各自性格

**节奏准确：**
- 紧张场景后必须有缓冲，连续三个紧张场景读者会疲劳
- 开篇信息密度要低（先抓人再解释），中段可以高，结尾要收
- 关键场景可以长，过渡场景必须短，能一句话说清的不写一段

**检查方法：**
- 细节考据：涉及专业领域时必须查证，不能凭印象
- 情感反应核对：人物遇到事件时，问"一个这样的人遇到这种事会怎么反应？"
- 节奏曲线分析：标出每个场景的紧张度（1-10），画出曲线，检查是否有连续高位或连续低位

---

### 9.5 丰富标准

**细节丰富：**
- 每1000字至少3个具体细节（不是通用描写）
- 细节必须服务于人物/氛围/主题，不是为了细节而细节
- 至少有一个"无用但有神"的细节（和情节无关但有生活温度，比如主角总把笔帽咬变形）

**人物丰富：**
- 主角必须有：欲望+缺陷+创伤+弧光+怪癖/习惯+秘密+过去
- 配角必须有：自己的欲望+自己的秘密（不能只是主角的工具人）
- 反派必须有：合理的动机+自己的逻辑（不能为了坏而坏）

**世界丰富：**
- 世界观必须有：表层规则+深层历史+边缘地带（不为人知的角落）
- 至少有一个"世界的秘密"（大部分人不知道的真相）
- 社会有阶层/群体/矛盾，不是铁板一块

**检查方法：**
- 细节密度：统计每1000字的具体细节数量，低于3个就加
- 人物深度：检查每个人物是否有至少3个维度（不只是"好人/坏人"）
- 世界观层次：检查是否有表层+深层+边缘三个层次

---

### 9.6 想象力标准

**每个阶段必须有想象力激发点：**

| 阶段 | 激发点要求 |
|------|-----------|
| 人物 | 至少1个"意想不到但合理"的人物细节（杀手喜欢织毛衣/医生怕血/律师口吃） |
| 世界观 | 至少1个"反常识但自洽"的规则（说谎会下雨/记忆可以买卖但没人想买） |
| 场景 | 每个场景至少1个"反常规"元素（葬礼上有人笑/婚礼上下大雪/急诊室里有人弹钢琴） |
| 对话 | 至少1处"意外的潜台词"（嘴上说没关系其实在原谅/嘴上说再见其实是永别） |
| 结构 | 至少1个"反套路转折"（英雄最后失败了但他不在乎/反派的动机比主角更合理） |

**想象力原则：**
- 意想不到，但又合理——为了意外而意外是烂片，意外但合理是神作
- 想象力不是天马行空，而是在逻辑框架内的意外
- 每个想象力元素必须能被前面的伏笔或设定支撑

**检查方法：**
- 问自己："这里有没有哪里太 predictable（可预测）？"
- 把 predictable 的地方问："如果反过来会怎样？如果意想不到的人做了意想不到的事会怎样？"
- 检查每个想象力元素是否有逻辑支撑

## 十、风格适配系统（v1.1 新增）

> 不同风格有不同的创作参数。阶段一确定风格后，所有后续创作在该风格参数下进行。

### 10.1 内置风格画像

| 风格 | 用词偏好 | 句子节奏 | 情绪表达 | 细节密度 | 叙事距离 | 创新倾向 |
|------|---------|---------|---------|---------|---------|---------|
| **冷峻** | 克制、名词动词为主、少形容词 | 短句为主、干脆 | 极度压抑、全靠动作泄露 | 中等、硬细节 | 远、客观 | 冷反转、黑色幽默 |
| **温暖** | 柔软、有温度的词 | 长短交错、舒缓 | 适度表达、但不煽情 | 高、生活细节 | 近、贴身 | 小确幸、意外的善意 |
| **荒诞** | 跳跃、反逻辑的比喻 | 不规则、突然断裂 | 一本正经地胡说八道 | 高、怪异细节 | 中、戏谑 | 设定荒诞但逻辑自洽 |
| **诗意** | 意象化、通感、留白 | 长句为主、有韵律 | 含蓄、全靠意象 | 高、感官细节 | 远、朦胧 | 意象创新、结构诗化 |
| **黑色幽默** | 调侃、冷面笑匠 | 快、punchline密集 | 用幽默掩盖悲伤 | 中等、讽刺细节 | 中、调侃 | 反套路、意外的笑点 |
| **致郁** | 压抑、灰色调词汇 | 慢、拖沓、重复 | 层层递进、最后一击 | 高、窒息细节 | 近、压迫 | 希望出现又破灭 |
| **史诗** | 宏大、书面化 | 长句、排比（适度） | 高亢、但有克制 | 高、历史细节 | 远、上帝视角 | 世界观创新、人物命运交织 |
| **日常** | 口语化、生活化 | 自然、不刻意 | 平淡中见真情 | 高、生活流细节 | 近、贴身 | 日常中的意外、小反转 |

### 10.2 风格使用规则

1. **阶段一确定风格**：小小羊/中心技能在引导开始时主动问"主编，这个故事想要什么风格？"，给3个风格选项+混合风格选项
2. **加载风格参数**：确定风格后，所有后续模块（人物/场景/对话/结构）自动加载对应风格参数
3. **混合风格**：支持主风格+副风格（如"冷峻+温暖"=外冷内热型），参数取主风格为主、副风格为辅
4. **风格一致性检查**：全文完成后，23-质量保障模块检查是否有风格漂移的段落，漂移段落标注并建议修改
5. **风格可扩展**：用户可以自定义风格，保存到创作边界档案中，下次直接调用

## 十一、全流程质量门禁（v1.1 新增）

> 每个阶段完成后必须通过门禁检查才能进入下一阶段。门禁不是为了卡人，是为了在早期发现问题，避免写完才发现根基不对。

| 阶段 | 门禁检查项 | 通过标准 | 不通过怎么办 |
|------|-----------|---------|-------------|
| **创意阶段** | ①创新点检查 ②独特性检查 ③情感动机检查 | 至少1个核心创新点+不是烂大街设定+有明确的"为什么想写" | 回到02-创意引擎重新生成，标注"上一个方向创新不足" |
| **人物阶段** | ①动机检查 ②缺陷检查 ③逻辑检查 ④人味检查 | 主角有欲望+为什么想要+有致命缺陷+行为可预测+有怪癖/习惯/过去 | 回到06-人物塑造深化，缺什么补什么 |
| **世界观阶段** | ①自洽检查 ②层次检查 ③创新检查 | 规则之间不矛盾+有表层/深层/边缘三层+不是通用设定 | 回到05-世界观构建补全 |
| **结构阶段** | ①冲突检查 ②转折检查 ③节奏检查 ④逻辑检查 | 核心冲突足够强+转折有伏笔且改变走向+张弛曲线合理+因果链完整 | 回到08-结构大纲调整 |
| **场景写作** | ①人味9条 ②细节检查 ③钩子检查 ④想象力检查 | 人味9条全过+细节具体不通用+场景结尾有钩子+至少1个意外元素 | 当场修改该场景，不进入下一场景 |
| **对话阶段** | ①潜台词检查 ②差异化检查 ③人味检查 | 不是所有人都说真心话+每个人说话方式不同+有打断/答非所问/不了了之 | 重写对话 |
| **初稿完成** | ①六维全面检查 ②风格一致性检查 ③伏笔回收检查 | 六维各维度无致命问题+风格无漂移+所有伏笔有回收 | 列出问题清单，按优先级修订 |
| **终稿** | ①六维质量评分 ②最终逻辑检查 ③内容审核 | 六维总分≥45/60+无逻辑漏洞+无敏感内容 | 针对性修订后重新评分 |

**门禁执行规则：**
1. 门禁由中心技能/小小羊在每个阶段结束时自动触发
2. 检查结果必须明确：通过/不通过+具体问题
3. 不通过时必须给出修改建议，不能只说"不通过"
4. 用户可以选择"跳过门禁"（但不推荐，跳过的风险由用户承担）
5. 门禁检查结果记录在项目档案中
